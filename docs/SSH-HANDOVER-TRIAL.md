## v1 native launch failure and regression correction

Returned v1 output ended with `No final result` and `sh: /tmp/nimbus-capture-ssh-v1/trial.sh: No such file or directory`. There was no worker identity output, TERM request or restart observation. Source inspection found the cause: sourcing the first-party inventory overwrote the launcher's generic `stage` variable with the temporary listener's stage. The detached shell therefore attempted the wrong script path and exited before entering the worker. The original trial markers/log remain evidence, not a completed stop/restore result. Fresh normal/replacement/Nimbus identities should still be checked rather than assuming state from absence of a log line alone.

The initial protocol mock did not model that sourced global-variable side effect. This was a helper/test defect, not a device or user-command error. A regression fixture reproduced the wrong worker path and also showed why the original RESULT path would have been unsafe had a worker been entered directly. The fix uses a dedicated **readonly `trial_stage`** for all worker/source/result paths and a distinct v2 stage. No script is moved into the temporary listener folder to work around the failure.

Corrected checkpoint: **176 tests run, 174 pass, 2 skips**. All fourteen handover tests pass.
